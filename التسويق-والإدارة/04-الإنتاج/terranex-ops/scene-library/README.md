# مكتبة المشاهد الذكية — Smart Scene Library

مكتبة مشاهد حقيقية قابلة للبحث والاسترجاع، تُغذّي الـstoryboard من `scene_id` بدل توقيتات
مكتوبة يدويًا. جزء من `terranex-ops` (التسويق فقط) — لا يمسّ التطبيق أو قواعده.

> **الأصل لا يُعدّل.** كل اللقطات من تصوير حقيقي متتبع في git (01 + 04). لا لقطات مختلقة،
> لا مسارات وهمية. الأوصاف كُتبت بمعاينة بصرية فعلية من وكيل Arena (لا واجهة vision آلية غير مثبتة).

---

## 1) البنية

```
scene-library/
├── index.json            ← الفهرس (مصادر + مشاهد) — متتبع في git، قابل للاستعادة
├── README.md             ← هذا الملف (تعليمات + استعادة)
├── .gitignore            ← يستبعد assets/ (الأصول الخام المنسوخة)
├── tags/agent-tags.json  ← وسوم/أوصاف كتبها الوكيل بعد المعاينة (شفافة، قابلة لإعادة التطبيق)
├── previews/             ← معاينة لكل مشهد + أوراق تلامس للمصادر — متتبعة
│   ├── contact_src-01.jpg, contact_src-04.jpg
│   └── s01-01.jpg … s04-05.jpg
├── storyboard/           ← storyboard مشتق من المكتبة
│   ├── spec-library.json          ← spec reel_build (التوقيتات من الفهرس)
│   ├── captions.json              ← نصوص الكابشن (نوافذها تُولّد من مدد المشاهد)
│   ├── make_visual.py             ← مولّد اللوحة البصرية
│   └── 09c-storyboard-visual.png  ← اللوحة البصرية
└── assets/               ← (خارج git) نسخ الأصول غير المتتبعة فقط — فارغة حاليًا
```

## 2) أين تعيش الأصول وكيف تُستعاد في جلسة جديدة

| المصدر | المسار (نسبي لجذر المستودع) | متتبع في git؟ | الاستعادة في جلسة جديدة |
|---|---|---|---|
| `src-01` | `التسويق-والإدارة/05-التسليم-والنشر/جاهز-للنشر/01-بومو-الشركة-الرئيسي.mp4` | ✅ نعم | `git checkout -- '<المسار>'` (يُستعاد تلقائيًا مع المستودع) |
| `src-04` | `التسويق-والإدارة/05-التسليم-والنشر/جاهز-للنشر/04-الأربعاء-الوزن-على-الطبيعة.mp4` | ✅ نعم | `git checkout -- '<المسار>'` |

- **لا تُرفع فيديوهات خام كبيرة إلى git تلقائيًا.** المصدران أعلاه موجودان أصلًا في المستودع
  (نسخ النشر الرسمية)، لذا تُشار إليهما في مكانهما ولا تُنسخ.
- أي ملف **جديد غير متتبع** يُنسخ إلى `assets/` (مستبعد من git). في جلسة جديدة **أعد رفع الملف
  الأصلي** ثم أعد `ingest` (يزيل التكرار بـSHA-256 تلقائيًا). حقل `restore` في الفهرس يوضح ذلك لكل مصدر.
- الفهرس والمعاينات والوسوم متتبعة → المكتبة نفسها تُستعاد كاملة من git؛ الأصول فقط قد تحتاج إعادة رفع.

## 3) خط الأنابيب (أوامر جاهزة)

```bash
# من مجلد terranex-ops:
python3 engine/scene_library.py ingest <فيديو1> <فيديو2>      # استيعاب + SHA-256 + أبعاد/مدة
python3 engine/scene_library.py analyze src-01               # كشف حدود FFmpeg + ورقة معاينة
python3 engine/scene_library.py analyze src-04
python3 engine/scene_library.py tag scene-library/tags/agent-tags.json   # وسوم المعاينة البصرية
python3 engine/scene_library.py search "الخروف على الميزان"   # استرجاع (id + توقيت + مسار)
python3 engine/scene_library.py list                         # سرد المصادر والمشاهد
python3 engine/scene_library.py storyboard \
    --scenes s01-02,s04-02,s01-08,s01-07 \
    --captions scene-library/storyboard/captions.json \
    --out scene-library/storyboard/spec-library.json
```

- **كشف الحدود:** FFmpeg `select='gt(scene,0.25)',showinfo` (لا حاجة لـPySceneDetect غير المثبت).
  اللقطات المتصلة (مثل 04) بلا قطع → تُقسّم يدويًا إلى مشاهد فرعية من المعاينة وتُوثّق في `tags/`.
- **الوسم:** يكتبه الوكيل بعد معاينة أوراق التلامس وإطارات كاملة الدقة. الحقل `tagged_by="arena-vision"`.
  لا توجد واجهة vision آلية غير مثبتة — لا ندّعي خلاف ذلك.

## 4) البحث (أمثلة حقيقية مُختبرة)

| الاستعلام | أعلى نتيجة | التوقيت | المصدر |
|---|---|---|---|
| «الخروف على الميزان» | `s04-02` | 4.0–11.0s | 04 |
| «أفضل لقطة وزن للخروف» | `s04-02` | 4.0–11.0s | 04 |
| «تغذية الأبقار» | `s01-08` | 19.0–21.033s | 01 |

يعيد البحث `scene_id` + `start/end` + `source_path` + `preview` + `description`. الترتيب حسب
تغطية الوسوم + الجودة، ويستبعد غير الصالح افتراضيًا. قاموس الوسوم عربي/إنجليزي
(خروف/sheep، ميزان/وزن/scale، تغذية/feeding، مزرعة/farm، شخص/person، نص-محروق/burned-text…).

## 5) الـstoryboard مشتق من المكتبة (لا توقيتات يدوية)

`storyboard()` يقرأ كل `start/end` من الفهرس عبر `scene_id`، ويولّد نوافذ الكابشن من مدد المشاهد،
ويأخذ المعالجة (`crop`/`proof_bar`) من وسوم المشهد. لا يوجد أي توقيت لقطة مكتوب يدويًا في كود الإنتاج.
أُنتج عن ذلك `spec-library.json` ثم رُندر عبر `reel_build` إلى:
`05-التسليم-والنشر/بانتظار-مراجعة-المالك/فيديوهات/2026-11/AD04-وزن-الخروف-مشتق-من-المكتبة-15ث.mp4`
(14.93s، 1080×1920، **مسودة بصرية صامتة** — الصوت/التعليق خطوة إنتاج لاحقة بوسم §3.5).

## 6) حدود معلنة (بصدق)

- **04 هو لقطة الوزن الحقلي** الموثقة بعنوان المصدر؛ المشهد يُظهر خروفًا مُمسكًا به على أرضية
  خرسانية ويد شخص تمسك رأسه. **لا تظهر منصة ميزان بوضوح في الكادر** — وُسم `scale` كنشاط الوزن
  الموثق، والوصف يصف ما شوهد فعلًا دون اختلاق ميزان ظاهر.
- مشاهد المتحدثين بوجوه ظاهرة (`s01-01/05/06/09`) **غير صالحة** (B10 — لا وجوه بلا موافقة).
- الإطارات الختامية (`s01-09`, `s04-05`) تحمل اسم مدينة (مخالف B9) → غير صالحة.
- معاينات الفهرس تعرض المصدر الخام (علامة «TerraNex LLC» ظاهرة)؛ الرندر النهائي يخفيها بشريط
  الإثبات المعتم (B11) كما في 09b/09c.

## 8) Creative Director v1.1 — من طلب عربي / JSON إبداعي إلى خطة قابلة للتنفيذ

`engine/creative_director.py` يبني على هذا الفهرس: يفهم طلبًا مصريًا محدودًا (متابعة/تغذية/وزن)،
أو يقبل `creative-input.json` يكتبه وكيل Arena. يختار المشاهد الصالحة ويرتّبها، يولّد hook وسكربت
وستوريبورد وspec نسبي المسارات، ثم يرندر عبر `reel_build`. كل توقيت مصدره الفهرس عبر `scene_id`؛
لا توقيتات مختلقة. ذاكرة المشروع وإصداراته في `output/creative-projects/<id>/` وتُستعاد بـ`show <id>`.

```bash
python3 engine/creative_director.py plan "اعمل إعلان 20 ثانية …" --project-id cd-followup-20s
python3 engine/creative_director.py apply-creative cd-feeding-15s   # يقرأ creative-input.json
python3 engine/creative_director.py revise cd-followup-20s "غيّر البداية، قلل لقطة الوزن، وقدم التغذية"
python3 engine/creative_director.py render cd-followup-20s
python3 engine/creative_director.py prove-relocation cd-followup-20s
```

بدون تعليق معتمد = **مسودة بصرية صامتة** موسومة، ولا تحصل على قرار نشر. عند توفر صوت معتمد:
`voice-input.wav` + `voice-transcript.json` بتفريغ بشري مطابق؛ `attach-voice` يرفض اختلاف النص ثم
يربط الكابشنات بقياس الطاقة. مسارات `spec-library.json` نسبية من مجلد الـspec (قابلة للنقل).
