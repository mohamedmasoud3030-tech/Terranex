## 2) لماذا Coverage على New Code = 0%؟
السبب الجذري: المشروع يستخدم **SonarCloud Automatic Analysis**، وهذا الوضع **لا يستورد تقارير التغطية** مهما كان ملف `coverage.xml` موجودًا أو مضبوطًا في الخصائص. لذلك 0% هنا فجوة تقرير، وليس دليلًا على عدم وجود اختبارات.

ما تم تنفيذه مجانًا:
- إضافة `coverage.py` (BSD-3-Clause) في `requirements-dev.txt`.
- إضافة `.coveragerc` يقيس `engine/` مع branch coverage.
- إضافة workflow جديد `Marketing Ops` يشغّل الاختبارات وselfcheck ويولّد `coverage.xml` ويرفعه كـ artifact باسم `terranex-ops-coverage`، بدون لمس تطبيق الاستثمار وبدون تعطيل أي بوابة.
- قفل تبعيات CI بـ hashes كاملة وتثبيتها بـ `--require-hashes --only-binary :all:`؛ اجتاز التثبيت والاختبارات في بيئة نظيفة.

أرقام التغطية الفعلية من التشغيل المحلي:
- تغطية إجمالية لكل `engine/`: ~40% (لوجود سكربتات قديمة غير مغطاة).
- تغطية النواة الجديدة/المعدلة (branch): **72%** تقريبًا:
  - `creative_director.py` 73%
  - `creative_store.py` 93%
  - `safe_paths.py` 84%
  - `reel_build.py` 78%
  - `qa_video.py` 54%
  - `critic.py` 49%

ما يلزم المالك لعرض التغطية في SonarCloud نفسه:
1. تفعيل **CI-based Analysis** بدل Automatic Analysis من إعدادات SonarCloud.
2. إضافة `SONAR_TOKEN` (وorganization/project key إن لزم) كأسرار/متغيرات GitHub.
3. تشغيل sonar-scanner بعد خطوة التغطية، مع ضبط مسار التقرير وإعادة كتابة مسارات الملفات لتكون repo-relative.
لم يتم شراء أي أداة، ولم يتم تعطيل أي بوابة، ولم يتم استبعاد ملفات جديدة.

## 4) دورة استعادة من جلسة نظيفة
تم تشغيل أوامر CLI في عمليات منفصلة على المشروع الحقيقي `cd-followup-20s`:

```bash
python3 engine/creative_director.py show cd-followup-20s
python3 engine/creative_director.py revise cd-followup-20s "قدم التغذية وقلل لقطة الوزن"
python3 engine/creative_director.py show cd-followup-20s
python3 engine/creative_director.py rollback cd-followup-20s 2
python3 engine/creative_director.py render cd-followup-20s --force
```

النتيجة:
- `show` قرأ الذاكرة schema v2 من القرص.
- `revise` أنشأ v3 فعليًا: `s01-08, s04-03, s04-02, s01-03, s01-07, s04-04`.
- `rollback` أعاد current_version=2 والحالة `visual-draft`.
- `render` أنتج فيديو 600 إطار / 20.0ث / 6 لقطات، وQA تقني pass مع تحذير صامت، وقرار النشر `غير جاهز للنشر`.

ملاحظة أمانة: أثناء دورة الاستعادة أنتج `render --force` مرةً container SHA مختلفًا عن دليل القبول المخزن، رغم أن عدد الإطارات والمدة مطابقان. بعد استعادة الحالة المتتبعة الأصلية، أعاد كل من CLI و`reel_build` إنتاج نفس SHA الأصلي تمامًا:
`413b8d45258042da0ebb4fde0660e74e0d5d4b96ace304047b97e15852ee4e98`
وframemd5 للإطار الأول/الأخير مطابق. لذلك أُعيد الأصل إلى حالته ولم يُستبدل دليل القبول. التوصية الإنتاجية: اعتماد hash على مستوى الإطارات أو إعادة الرندر من حالة Git نظيفة عند مقارنة الأدلة، وعدم افتراض أن container SHA مستقر عبر كل جلسة/حمل نظام.

## 5) تقييم التعليق الصوتي المصري المجاني داخل Arena
ما تم فحصه فعليًا:
- لا توجد حزم TTS محلية مثبتة: لا `edge-tts`، لا `TTS`، لا `piper`، لا `espeak/pyttsx3`، ولا ASR محلي.
- قائمة الشبكات المسموحة في البيئة لا تشمل خدمات TTS تجارية/سحابية؛ لذلك لا يمكن افتراض توفر اتصال بها.
- أدوات Arena للكلام موجودة كإمكانية منصة (`add_voice`/`generate_speech`)، لكن لهجة `ar-EG` وجودة الصوت/trخيصه التجاري لم يتم التحقق منهما في هذه المراجعة، ولا يجوز افتراض أنهما مجانيان/احترافيان أو مطابقان لهوية الصوت المعتمدة.
- بدائل مفتوحة مثل Piper/Coqui/espeak-ng تحتاج نماذج وترخيصًا مناسبًا؛ لا يوجد نموذج مصري احترافي مثبت هنا. espeak-ng آلي/روبوتي ولا يصلح كصوت علامة.

**النتيجة:** لا يوجد تعليق صوتي مصري مجاني احترافي تم اختباره واعتماده داخل هذه البيئة. لا يتم تغيير هوية الصوت المثبتة، ولا يتم إرفاق أي صوت مولّد كصوت معتمد.

## 6) مسار إرفاق تسجيل بشري معتمد (البديل الجاهز)
عند توفير تسجيل بشري من المستخدم/المالك:
1. يوضع التسجيل باسم مسموح داخل مجلد المشروع: `voice-input.wav` (أو mp3/m4a/flac/ogg).
2. يوضع `voice-transcript.json` مطابق للسكربت، مع:
   - `verification_method: "human-reviewed"`
   - `reviewer`
   - `approval_note`
   - عبارات منطوقة مطابقة لكل phrase في الخطة.
3. يُشغّل:
   ```bash
   python3 engine/creative_director.py attach-voice <project-id> --approval-note "موافقة المالك على التسجيل البشري"
   ```
4. البوابة ترفض: عدم وجود transcript، اختلاف النص، عدد عبارات غير مطابق، أو غياب المراجعة البشرية. قياس الطاقة وحده لا يكفي.
5. بعد الاجتياز، يُعاد الرندر ويظل قرار النشر منفصلًا حتى يسجل المالك قرار النشر الفعلي.
