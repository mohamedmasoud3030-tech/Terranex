# Terranex Greenfield

Terranex is an Arabic-first Investment Operations OS for Egyptian and MENA private investment operators. It is being rebuilt as a clean Greenfield product; legacy code is frozen and non-authoritative.

## Current status

- Phase: Real Estate (S0–S7/GF-010/GF-011), Agriculture (GF-013–GF-019), and Livestock (GF-020–GF-024) are technically implemented for their authorized scopes.
- R0 — Canonical Portfolio Realignment & Anti-Hallucination Governance — is merged. R1 — Portfolio Foundation — is merged (PR #139): the Organization → Investment Portfolio → Investment Project management hierarchy with a narrow lifecycle, one current parent Portfolio per Project, and append-only membership history.
- Procurement & Shared Operations (R4) is **complete** for the authorized flows (GF-025/GF-026 + ADR 0030/0031): organization-scoped Suppliers, project-scoped Purchase Requests/Orders with commercial terms, Receiving (quantity-only operational truth), supplier invoices with receipt matching, Finance Core payable posting, maker/checker payment proposals, and bank reconciliation — with RLS, audit, and the Arabic/RTL workspace at `/projects/[projectId]/procurement`. See ADR [`0030`](docs/decisions/0030_R4_PROCUREMENT_FINANCIAL_INTEGRATION.md) and [`0031`](docs/decisions/0031_R4_PROCUREMENT_CONTRACTS_EVIDENCE.md) in `docs/decisions/` (the R4 closeout audit itself is in Git history, removed 2026-10-22).
- S0-S7, GF-010, GF-011, and GF-012 are merged to `main`; the permanent realistic Real Estate showcase (`DEMO-RE-2026-001`) remains preserved as explicitly synthetic data.
- GF-013 expands `investment_projects.sector` to `REAL_ESTATE | AGRICULTURE` and ships Agriculture as a sibling feature under `src/features/agriculture`. No second ledger, no second audit trail, no weakened RLS, no fabricated finance.
- Architecture: one Next.js modular monolith + one Supabase/PostgreSQL backend, Arabic/RTL and EGP-ready, with bounded Real Estate, Agriculture, and Livestock sector contexts.
- Hosted operator workspace: Real Estate keeps its nine business sections unchanged; Agriculture has its own project-scoped Arabic/RTL workspace at `/projects/[projectId]/agriculture` for land control, Farm/Field/CropCycle operations, activities, inputs, harvest/inventory, and bounded sales/collection. Project creation requires an explicit sector (`عقارات` / `زراعة`).
- **Status boundary:** Real Estate (S0–S7/GF-010/GF-011), Agriculture (GF-013–GF-019), and Livestock (GF-020–GF-024) are technically implemented for their authorized scopes. R0 — Canonical Portfolio Realignment & Anti-Hallucination Governance — is merged. No real customer UAT, paid pilot, or commercial validation is claimed. The synthetic demo is never customer evidence and Phase 2/3 remain not passed.
- **Money is currency-qualified (ADR 0034 / the H1 tranche).** There is no FX contract in this repository, so no server-rendered surface adds amounts in different currencies and prints the result under the project's reporting currency. Cash, capital and the management operating result are read per currency from the `*_by_currency` read models and rendered one labelled line per currency. `src/shared/money/by-currency.ts` is the only sanctioned roll-up and cannot return a scalar total; `/overview`, `/revenue`, `/costs`, `/cash` and `/budget` are pinned to it by `tests/currency-safe-pages.test.ts`. See [`docs/decisions/0034_H1_PROJECT_RESULT_TRUTH_AND_PROJECT_BRIEF.md`](docs/decisions/0034_H1_PROJECT_RESULT_TRUTH_AND_PROJECT_BRIEF.md).
- **Interface layer:** `src/app/globals.css` is a tokenised design system (semantic colour, type scale, spacing, sector identity for the three verticals), with an Arabic-first RTL type scale, tabular figures on comparable numbers, labelled table captions and column scopes, per-route `error.tsx`/`loading.tsx` boundaries, and WCAG 2.2 AA contrast measured from the tokens by test. Guidelines: [`docs/design/UI_UX_GUIDELINES.md`](docs/design/UI_UX_GUIDELINES.md), generated route review: [`docs/design/ROUTE_REVIEW.md`](docs/design/ROUTE_REVIEW.md).
- **Verified baseline** (2026-10-06, this mainline): `npx tsc --noEmit` clean · `npx eslint .` clean · `npx vitest run` **74 files / 1061 tests passing** · `npm run build` clean over **36 routes** · authenticated routes smoke-rendered against the offline preview harness (`scripts/ui-preview/`) with per-currency money confirmed in the served HTML. **Not verified here:** `npm run db:test` (the recovery environment had no `psql` and no `docker`), so the SQL suites' current status is unconfirmed and no database claim below rests on this run.
- **Next construction sequence:** the canonical roadmap is **R0–R17** with the hard stop at **R13**. **R1–R13 are complete** (see [`docs/ROADMAP_R0_R17.md`](docs/ROADMAP_R0_R17.md)), so the project is at the hard stop: the only gate forward is the **R14 owner policy pack** — the twelve decisions BD-001…BD-012 in [`docs/specs/owner/R14_TARGET_COMPANY_DECISION_PACK_AR.md`](docs/specs/owner/R14_TARGET_COMPANY_DECISION_PACK_AR.md), all OPEN until the authorized owner answers. Until then, investor-economics surfaces stay policy-inert by migration `20260816062000`, and R15–R17 (investor economics, distribution/statements, final UAT) do not start. Independent sector work, security/data-integrity fixes, and bounded product work remain allowed.
