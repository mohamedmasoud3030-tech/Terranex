# Terranex ADR Template

Use the next available number in docs/decisions and match the repository naming convention.

## Title

ADR NNNN — concise decision title

## Status

Proposed | Accepted | Superseded

## Context

- What decision is required?
- What current implementation facts matter?
- Which canonical documents or earlier ADRs constrain the choice?
- Which OPEN_BUSINESS_DECISIONS items remain relevant?
- What is explicitly outside scope?

## Decision

State the chosen architecture in concrete terms.

## Options considered

For each serious option:
- description;
- benefits;
- risks;
- rejected reason or conditions under which it would become preferable.

Include "keep the current design" when it is a credible option.

## Trade-offs

Cover only dimensions that matter to this decision:
- correctness;
- security and tenant isolation;
- data integrity;
- complexity;
- migration and rollback;
- operability;
- performance;
- testability;
- coupling.

## Verification

Describe how implementation will prove the decision:
- tests or SQL gates;
- migration or upgrade checks;
- security checks;
- UI or accessibility checks;
- operational evidence.

## Revisit triggers

List observable conditions that would justify reopening the ADR.

## Sources
