# دليل إرشادات وأفضل ممارسات UI/UX — Terranex

> **الإصدار:** v1 — مبني على فرع `design/ui-ux-upgrade` (PR #176)
> **المرجعية المنهجية:** مستلهى من [ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) (قواعد UX كبيانات: افعل/لا تفعل/خطورة/كود) ومن [shadcn/ui](https://github.com/shadcn-ui/ui) (التكوين أولًا، التوكنز الدلالية، أزمة كود صح/خطأ).
> **ملاحظة:** هذا الدليل بالعربية لأن جمهوره المباشر هو صاحب المشروع؛ ويُقتراح إصدار إنجليزي مطابق قبل اعتماده وثيقةً رسمية في المستودع (لغة التوثيق القائمة إنجليزية).

---

## متى يُطبَّق هذا الدليل (مستلهى من «When to Apply / Skip» في ui-ux-pro-max)

**طبّقه عندما:** تبني صفحة أو قسمًا جديدًا، تنشئ أو تعدّل مكونًا مشتركًا، تختار ألوانًا/خطوطًا/تباعدًا، تراجع كود واجهة، تضيف جدول بيانات أو حالة مالية، تعدّل التنقل أو النماذج أو حالات التحميل/الخطأ/الفراغ.

**لا تحتاجه عندما:** عمل خلفي صرف (DB/RLS/API)، أو تحسين أداء لا يمس الواجهة، أو بنية تحتية.

**معيار الحسم:** إذا كان التغيير يبدّل *كيف تبدو الشاشة، أو كيف تُستخدم، أو كيف تُقرأ أرقامها* — فهذا الدليل ينطبق.

## 1) الوصولية — حرجة

### 1.1 التباين
- **افعل:** كل توكن نصي ≥ 4.5:1 على كل خلفية يمكن أن يجلس عليها (المشروع يقيسها من التوكنز في `tests/design-system.test.ts` — وقد اكتشف فشلًا حقيقيًا في `--muted-2` عند 3.77:1 وتم إصلاحه).
- **لا تفعل:** «رمادي على رمادي»، أو تباين محسوب بالعين فقط.

### 1.2 الجداول
- **افعل:** كل `<table>` له اسم متاح (`aria-label` أو `aria-labelledby`)، وكل خلية رأس `scope="col"`. الـ PR غطّى 81/81 جدولًا.
- **لا تفعل:** جدول بلا رأس، أو رؤوس بتعبيرات JSX بلا اسم.

```tsx
// ✅ صح
<table aria-labelledby="suppliers-heading">
  <thead>
    <tr><th scope="col">المورد</th><th scope="col" className="num">الرصيد المفتوح</th></tr>
  </thead>

// ❌ خطأ
<table>
  <thead><tr><td>المورد</td><td>الرصيد</td></tr></thead>
```

### 1.3 تسمية الأقسام بعناوينها
- **افعل:** `<Section>` يربط القسم بعنوانه عبر `aria-labelledby` تلقائيًا.
- **لا تفعل:** `<section className="card">` يدوي بلا ارتباط (122 حالة `h2` مجرّدة ما تزال في الكود — انظر خطة العمل).

### 1.4 لا حالة باللون وحده
- **افعل:** كل نغمة حالة (نجاح/تحذير/خطر/معلومة/محايد) تحمل glyph عبر `.status::before`، والنغمات المفتوحة `.tone-open`/`.tone-void` متمايزة بلا لون.
- **لا تفعل:** أخضر/أحمر فقط للدلالة على النجاح/الخطأ.

### 1.5 التركيز
- **افعل:** `--focus` لون مستقل عن البراند (لا يُخلط بين «محدَّد» و«مركَّز عليه»)، وحلقة `:focus-visible` مرئية دائمًا.
- **لا تفعل:** إزالة outline بلا بديل، أو `z-index` يدوي فوق المكونات العائمة.

## 2) التفاعل ولوحة المفاتيح — حرجة

- ترتيب Tab يطابق الترتيب البصري؛ اختبر كل فعل بلا فأرة.
- عناصر تفاعلية بحجم لمس كافٍ (44px منطقي للويب عالي الكثافة قابلًا للنقاش، لكن لا أزرار أقل من 24px مع تباعد).
- لا تعتمد على hover وحده لإظهار معلومة أو فعل (قاعدة من ui-ux-pro-max: «Touch & Interaction»).
- قوائم `<details>` أصلية في `Section collapsible` تعمل بلا hydration وبلا JS — حافظ على ذلك.

## 3) حالات التحميل والخطأ والفراغ — عالية

| الحالة | المكوّن القياسي | البديل المرفوض |
|---|---|---|
| تحميل مسار | `PageSkeleton` في `loading.tsx` | سبينر معلّق أو شاشة بيضاء |
| خطأ مسار | `RouteError` في `error.tsx` | انفجار الـ stack أو رسالة إنجليزية خام |
| لا بيانات | `EmptyState` + فعل تالٍ | جدول فارغ بلا تفسير |
| لا صلاحية | `PermissionState` | إخفاء صامت أو 403 خام |
| تنبيه داخل الصفحة | `Banner` | div ملوّن يدوي |

قواعد مستلهامة من ui-ux-pro-max (قاعدة Empty States وLoading Indicators وSubmit Feedback):
- **الفراغ حقيقة + خطوة تالية:** «لا موردين بعد — أضف أول مورد» وليس مجرد «لا توجد بيانات».
- **التغذية الراجعة فورية:** حالة إرسال واضحة (تعطيل الزر + مؤشر) ثم نجاح/فشل، لا تجميد صامت.
- **`aria-busy`/`role="status"`** لحالات التحميل (مطبق بالفعل في `PageSkeleton` — حافظ عليه).

## 4) التكوين من المكوّنات المشتركة — عالية (منهج shadcn: «Compose, don't reinvent»)

**المبدأ:** إذا وُجد primitive في `src/shared/ui` — استخدمه ولا تكتب HTML يدويًا. المكون المشترك يضمّن الدلالة والوصولية والتوكن معًا.

### خريطة «مكوّن بدل ماركب يدوي»

| بدلًا من… | استخدم… |
|---|---|
| `<header>` يدوي بعنوان وزر | `<PageHeader eyebrow title description actions badge backHref>` |
| `<section className="card stack">` يدوي | `<Section title>` (يعطي `aria-labelledby` مجانًا) |
| `<div className="stat">` يدوي | `<StatGrid>` + `<Stat label value hint href tone>` |
| `<span>` ملوّن لحالة | `<StatusBadge tone>` (خمس نغمات دلالية) |
| div تنبيه مخصّص | `<Banner tone role>` |
| «لا توجد بيانات» يدوي | `<EmptyState title description action headingLevel compact>` |
| سبينر/شاشة فارغة | `<PageSkeleton blocks withNav>` |
| تبويبات يدوية بروابط | `<SectionTabs>` / `<InPageTabs>` |
| شريحة قطاع يدوية | `<SectorChip sector>` |
| رقم كبير بلا سياق | `<Figure value basis asOf negative>` |

### قواعد مكيفة من قواعد shadcn الحرفية

- **`className` للتنسيق الموضعي فقط، وليس لتجاوز ألوان المكوّن أو طباعته** (shadcn: *className for layout, not styling*).
- **المتغيّرات الدلالية قبل الأنماط اليدوية:** استخدم `tone`/`headingLevel`/`compact` المتاحة في المكون قبل كتابة CSS جديد.
- **الأيقونات كائنات لا مفاتيح نصية**، وبلا أصناف تحجيم داخل المكونات (shadcn icons rule).
- **الحاويات العائمة (dialog/menu) تحمل عنوانها دائمًا** — إن أُضيفت مستقبلًا، `DialogTitle` أو ما يعادله إلزامي للوصولية.
- **الزر لا يحمل `isLoading`**: ركّب (تعطيل + مؤشر) كما يفعل المشروع في نماذجه.

**مثال من الكود الفعلي:**

```tsx
// ✅ تكوين صحيح — كل شيء من المكونات المشتركة
<PageHeader eyebrow="المحفظة الاستثمارية" title="مشاريع العقارات" badge={<SectorChip sector="REAL_ESTATE" />} />
<Section title="أوامر الشراء المفتوحة" description="بانتظار الاستلام">
  {orders.length === 0
    ? <EmptyState title="لا أوامر شراء بعد" description="أنشئ أول أمر شراء للمشروع" action={<Link className="button" href="…">أمر شراء جديد</Link>} headingLevel={3} />
    : <table aria-labelledby="…">…</table>}
</Section>

// ❌ تدوير يدوي — نفس الشكل، دلالة أضعف، انحراف مضمون مع الوقت
<section className="card stack">
  <h2>أوامر الشراء المفتوحة</h2>
  <p className="muted">لا توجد بيانات</p>
</section>
```

## 5) RTL والاستجابة — عالية

- **خصائص منطقية فقط** في CSS: `inset-inline`، `border-inline`، `margin-inline` — لا `left/right` إطلاقًا (قاعدة مؤسِّسة في `globals.css`).
- الأرقام محاذاة-end داخل RTL عبر `.num` — مضمنة، لا تعِد اختراعها.
- الجداول العريضة: تمرير أفقي مُتحكَّم به أو تحويل لمكدس بطاقات على الموبايل (وضع table stack موجود فعلًا في المشروع) — لا كسر تخطيط.
- **الهدف 360px** معلن في نقاط الانكسار لكنه **لم يُفحص على جهاز حقيقي بعد** (فجوة معترف بها في ROUTE_REVIEW) — انظر خطة العمل.

---

## 6) التوكنز والطباعة واللون — متوسطة (منهج shadcn: ألوان دلالية لا خام)

- **لا لون حرفي خارج كتلة `:root`** — اختبار `design-system.test.ts` يُفشل البناء عند مخالفتها (يعادل قاعدة shadcn: «No raw hex in components»).
- الألوان الدلالية: `--success/--warning/--danger/--info` كلٌّ برمته ink + wash + edge — لا تركيب يدوي لدرجات.
- **هوية القطاع ≠ معنى:** `--sector-*` للهوية فقط (شريحة/سكة/glyph)، والحالة دائمًا من `StatusBadge` المجاور. بطاقة المحفظة بلا قطاع تأخذ سكة محايدة.
- التركيز `--focus` ليس لون البراند — عمدًا.
- **الأرقام الجدولية إلزامية** أينما يقارَن رقمان: `.num` / `.stat-value` / `.facts dd` (بدونها `1,234,567.89` لا يصطف مع `987,654.32`).
- لا Webfont خارجي — التطبيق يعمل offline بلا طلبات طرف ثالث (حافظ على ذلك).
- الطباعة: kufi/display للعناوين، نص للجسم، `--fs-300…800` — لا أحجام مخصصة.

---

## 7) الحركة — متوسطة

- `prefers-reduced-motion` مدعوم — أي حركة جديدة يجب أن تحترمه.
- مدة واحدة لكل شيء خطأ (قاعدة ui-ux-pro-max): تفاعلات hover قصيرة (150–250ms)، انتقالات أثقل فقط حيث معنى مكاني.
- لا تُحرّك `width/height` (layout thrashing) — حرّك transform/opacity.
- العمق من الحدود لا الظلال (فلسفة المشروع: نظام مالي جاد) — لا تُضف ظلالًا زخرفية.

---

## 8) النماذج والتغذية الراجعة — متوسطة-عالية (من قواعد ui-ux-pro-max النموذجية + أنماط shadcn)

- **تسمية ظاهرة لكل حقل** (`label` مرتبط بـ `for`) — لا placeholder بديلًا عن التسمية.
- **تحقق فوري عند blur** لمعظم الحقول، مع بقاء الأخطاء مرئية قرب الحقل.
- **ملخص أخطاء قابل للتركيز** أعلى النموذج عند فشل الإرسال، يربط كل بند بحقله، مع بقاء الأخطاء السطرية.
- **الإرسال idempotent** — المشروع يختبر ذلك بالفعل في `*-forms-idempotency.test.tsx`؛ أي نموذج جديد يحتاج اختبارًا مماثلًا.
- خيار من 2–7 بدائل؟ مجموعة أزرار خيار (ToggleGroup-like) لا أزرارًا يدوية بحالة نشطة يدوية (shadcn).
- زر الإرسال: تعطيل + مؤشر أثناء التنفيذ، ثم نجاح/فشل واضح.

---

## 9) التنقل — عالية

- **التنقل المُجمّع `WorkspaceNavGrouped`** أربعة مجموعات مسماة — العضوية معلنة صراحة في `GROUP_SPECS` ومحروسة بـ `assertSectionGroupingIsExact()` و20 اختبارًا. أي قسم جديد يُضاف لـ `sectionsFor()` يجب تعريف مجموعته صراحة.
- **الحالة النشطة واضحة** لقسم المستخدم الحالي.
- **لا روابط ميتة:** اختبار `in-page-navigation.test.ts` يفحص كل href تبويب مقابل معرّفات فعلية في الصفحة — وجّه كل anchor لـ `id` موجود.
- **ترتيب بالقرار لا بالعرض:** الاستثناءات غير المحسومة قبل الأرقام (انتباه قبل مال).

## 10) البيانات المالية والجداول — قاعدة Terranex الخاصة

كل رصيد يحمل ثلاثية:

1. **أساسه** (مِمَّ حُسِّب) — `basis`
2. **«كما في»** (متى كان صحيحًا) — `asOf`
3. **عملته**

```tsx
<Figure basis="النقدية" value={formatMinorUnits(cash, currency)} asOf="بعد التحويل المعتمد" />
```

- لا `Number()` ولا `parseFloat` ولا `toFixed` في مسارات المال — bigint ب وحدات صغرى عبر `formatMinorUnits`.
- **لا أكواد enum خام على الشاشة** (`PENDING`/`OWNER` إنجليزيةً في واجهة عربية): `recordStatusLabel()` و`roleLabel()` مع fallback للكود الخام لا للتخمين.
- عرض 4 أرقام قرار أولًا ثم الإفصاح عن البقية (فصل قرار-حرج عن مساند) — نمط «قرار قبل زخرفة».
- roll-up لوحة قيادة ≠ ترخيص دفتر جديد أو سلوك محاسبي عابر للمشاريع (قاعدة AGENTS الحاكمة).

## كيف تُفرض هذه الإرشادات آليًا (دروس من المستودعين)

من **ui-ux-pro-max-skill** تعلمنا أن القاعدة غير القابلة للفحص تنزف: قواعدهم CSV بدرجة خطورة وكود قابل للفحص. من **shadcn/ui** تعلمنا أن القاعدة تكتب كزوج «خطأ/صح». المشروع يجمعهما فعلًا عبر الاختبارات:

1. **وسّع `tests/design-system.test.ts`** بكل قاعدة جديدة قابلة للفحص النصي (مثل: لا `<section className="card` خارج `src/shared/ui` — يمكن رفع نسبة تبنّي `Section` تدريجيًا بعتبات صريحة).
2. **أزمة اختبار `empty-state` درسٌ ماثل:** الحارس الذي يعتمد على ترتيب الـ classes ليس حارسًا — حاولتان حقيقيتان في agriculture هربتا من regex `card(?: stack)? empty` لمجرد كتابتهما `card empty stack`. أي فحص نصي على markup يجب أن يكون حساسًا للترتيب (`card[^"]*\bempty\b`).
3. **أضف اختبار «لا enum خام»**: grep للقيم التي تسمح بها قيود CHECK مقابل دوال التسمية.
4. **اجعل `ROUTE_REVIEW.md` بوابة دمج**: إعادة توليده في CI وفشل البناء عند انحراف العدادات (اسم جدول بلا اسم = انحدار) — الخيار `--check` موجود جاهزًا في السكربت.
5. **وثّق القاعدة الجديدة كزوج كود صح/خطأ** في هذا الدليل أولًا، ثم حوّلها لاختبار — القاعدة تعيش حيث تُفحص.
