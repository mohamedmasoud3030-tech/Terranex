# Terranex Design System

**Status:** v1 — shipped with the UI/UX upgrade branch
**Scope:** the user-facing surface of the existing operator product. Nothing here changes a route, a permission, a business rule, a domain term, or a data source.

Open **[`design-system.html`](./design-system.html)** in a browser to see the system rendered. That file is generated by `scripts/build-design-gallery.mjs`, which **inlines `src/app/globals.css` itself** — so the specification cannot drift from the shipped CSS. Regenerate it after any stylesheet change:

```bash
node ./scripts/build-design-gallery.mjs
```

---

## 1. What Terranix is, and what the interface must therefore do

Terranix is an **Arabic/RTL-first Investment Operations OS**. Its user is an investment operator running their own Real Estate, Agriculture, and Livestock projects — not a retail investor browsing opportunities.

That single fact governs every decision below. The interface's job is not to persuade anyone to invest. It is to let an operator **see the truth of an asset, act on it deliberately, and prove afterwards what they did.**

Consequently the design standard is:

> **Every number says where it came from. Every state is understandable without colour. Every consequential action explains its effect before it can be submitted.**

A screen that looks impressive while making an investment fact harder to verify is a failure of this system, however good it looks.

## 2. Design tokens

All colour lives in `:root` in `src/app/globals.css`. **No literal colour may appear outside that block** — `tests/design-system.test.ts` fails the build if one does.

| Group | Tokens | Purpose |
|---|---|---|
| Brand | `--brand` `--brand-strong` `--brand-hover` `--brand-soft` `--brand-softer` `--brand-ink` | Deep pine. Calm, serious, evidence-oriented. |
| Foreground on brand | `--on-brand` `--on-brand-strong` `--on-brand-muted` `--on-brand-faint` | The ramp for the dark auth panel and brand mark. |
| Neutrals | `--ink` `--ink-2` `--muted` `--muted-2` `--line` `--line-strong` `--line-soft` `--paper` `--paper-2` `--surface` `--surface-sunken` | Hierarchy without decoration. `--muted` is 4.8:1 on white. |
| Status | `--success` `--warning` `--danger` `--info` each with `-ink` `-wash` `-edge`, plus `--neutral-*` | Every tone ships a foreground, a wash and an edge so a badge never relies on hue alone. |
| Sector | `--sector-{real-estate,agriculture,livestock}` each with `-ink` `-wash` `-edge` | Identity for the three verticals. Ochre / green / clay at matched saturation. |
| Focus | `--focus` `--focus-ring` | Deliberately **not** the brand colour, so a focused control is never mistaken for a selected one. |
| Type | `--font-ui` `--font-display` `--font-num` `--fs-300…800` `--tnum` | Arabic-first. Display/body split. |
| Space / radius / elevation / motion | `--sp-1…10` `--r-sm…pill` `--sh-1…3` `--dur-1` `--dur-2` `--ease` | 4px base scale. Small radii — a financial system reads serious. Depth comes from borders, not shadow. |

### Typography

Arabic is the authored source language. Headings use a kufi/display face (`Noto Kufi Arabic` → `Noto Sans Arabic` → `Segoe UI` → `Tahoma`), body uses a text face. **No webfont is fetched**, so the app renders identically offline and adds no third-party request.

**Tabular figures are mandatory** wherever two numbers can be compared:

```css
--tnum: "tnum" 1, "lnum" 1;
```

Applied via `.num` to money and quantity cells, `.stat-value`, `.overview-kpi strong`, `.metric strong`, and `.facts dd`. Without it, `1,234,567.89` and `987,654.32` do not line up and cannot be compared at a glance.

## 3. The three verticals, one system

Real Estate, Agriculture, and Livestock are three coherent verticals inside one product — not three applications. They share geometry and differ in hue:

| Vertical | Arabic | Accent | Glyph |
|---|---|---|---|
| Real Estate | عقارات | `--sector-real-estate` (ochre) | parcel with a building line |
| Agriculture | زراعة | `--sector-agriculture` (green) | two leaves on a stem |
| Livestock | ثروة حيوانية | `--sector-livestock` (clay) | herd head |

**The accent is identity only. It never encodes meaning.** State always comes from the adjacent `StatusBadge`. A colour that means nothing is worse than no colour — which is why a portfolio card (`.project.no-sector`) gets a neutral rail: a portfolio is not a sector object.

Set the theme on any container and its children inherit the vertical:

```tsx
<li className={SECTOR_THEME_CLASS[project.sector]}>
  <Link className="project" href={…}>…</Link>
</li>
```

Constants live in `src/features/workspace/sectors.ts` — dependency-free on purpose, so both `src/shared/ui` and feature label modules can import them without a cycle.

## 4. Information architecture

### Decision order, not decoration order

Screens are ordered by what the reader needs to decide, not by what is easiest to render. On the executive home that means **attention before money**: an unresolved integrity exception means the figures below it may not be trustworthy yet, so the exceptions render first.

### Grouped workspace navigation

A project workspace had **13 unlabelled tabs in one row**. That cannot be scanned. `WorkspaceNavGrouped` presents the same sections in four named groups:

| Group | Contents |
|---|---|
| sector | the vertical's own operating sections |
| المال | رأس المال · التكاليف والنقدية · الإيراد والبيع · الإغلاق المالي |
| الشفافية والاستيراد | شفافية المشاركين · الاستيراد والمطابقة |
| الرقابة والحوكمة | المشتريات · الموازنة · مركز النزاهة · المخاطر والقرارات |

**Grouping is a view over `sectionsFor()`, never a superset of it.** Membership is declared explicitly in `GROUP_SPECS` — deriving it by exclusion put every section in the sector group and duplicated six of them, because `sectionsFor('REAL_ESTATE')` returns the finance sections inside its own list. `assertSectionGroupingIsExact()` throws at runtime if a section is missing, duplicated, or invented, and `tests/workspace-nav-grouping.test.ts` (20 tests) locks the invariant, including that livestock never gains the real-estate money sections.

No route, href, label, or permission changed.

### Separating decision-critical from supporting

The portfolio roll-up was a 14-column table. It now leads with the four figures an owner decides on (cash, open payables, realized result, open exceptions) per currency, with the remaining ten columns one disclosure away. Nothing was removed; the ordering changed.

## 5. Financial legibility

A number alone is not information. Every balance carries:

1. **its basis** — what it was computed from;
2. **its "as of"** — when it was true (`.as-of`);
3. **its currency**.

```tsx
<Figure basis="النقدية" value={formatMinorUnits(cash, currency)} asOf="بعد التحويل المعتمد" />
```

Rules that follow from the product's anti-hallucination governance:

- **Never render a zero in place of a missing fact.** Show the reason. `src/app/(app)/assets/page.tsx` already does this and is the reference implementation: an operator must be able to tell "cost not entered yet" apart from "this asset kind has no acquisition cost" apart from "worth zero".
- **When a metric is blocked by an unresolved business rule, say so** using the canonical pattern — `<strong>غير محدد بسياسة معتمدة</strong>` plus the missing-decision context. Never a zero, never an industry estimate.
- **Money columns are end-aligned with tabular figures.** `scripts/align-money-columns.mjs` applies this across the finance tables, deciding which columns are financial **from the column's own Arabic header** rather than guessing from cell contents. It is idempotent and skips cells with a dynamic `className={…}`.
- **No percentage without its basis. No return without its date range.**

## 6. Status is never colour alone

Every status pill draws a glyph from `::before`, so state survives greyscale printing, colour-vision deficiency, and a screen reader:

| Shape | Meaning | Class |
|---|---|---|
| solid dot | settled / complete / positive | *(default)* |
| ring | open / in flight / awaiting | `.tone-open` |
| bar | void / cancelled | `.tone-void` |

Three vocabularies are kept visually distinct on purpose, because conflating them misleads the reader:

- **Record status** (`.status.badge-*`) — the state of a thing.
- **Role** (`.role-badge`, `.role-badge.owner`) — a person's authority over an action. "مالك" is not a state of a record.
- **Intake readiness** (`.intake-badge-*`) — completeness of an evidence section.

## 7. Consequential actions

Every mutating form in the product follows one pattern, and it is the pattern
that carries the safeguard — there is no separate confirmation component:

```tsx
const [state, action, pending] = useActionState(postClosingEntry, initial);
<form action={action} className="form-grid">
  <Context {...{ organizationId, projectId }} />
  <Key prefix="close-post" state={state} />   {/* idempotency key, hidden */}
  {/* …fields, each with its own <label>… */}
  <div className="full"><Result {...{ state, pending }} label="ترحيل قيد الإغلاق" /></div>
</form>
```

The operator reads the effect in the section they are already in; the button
names the act ("ترحيل قيد الإغلاق", not "حفظ"); `pending` disables it so a
double press cannot double-post; and the hidden idempotency key means a
retried submit is recognised rather than repeated. Server actions plus RLS
are the real gate — the interface never has to be the only thing standing
between an operator and a write.

Safeguards are not friction to be optimised away. One primary action per
screen; the dangerous variant never looks like the primary one; cancel is
always available and always visually separated (`margin-inline-start: auto`).

## 8. States

Seven states, each visually distinct:

| State | Component / class |
|---|---|
| loading | `PageSkeleton` (`.skeleton-*`), respects `prefers-reduced-motion` |
| empty | `EmptyState` |
| filtered-empty | `EmptyState` with a way back to the unfiltered view |
| error | `error.tsx` + `ErrorState` |
| no access | `PermissionState` |
| not defined by approved policy | `.banner.info` with the canonical phrase |
| attention | `.banner` / `.banner.warning` / `.banner.info` |

Empty states never contain invented data. A first-run account starts empty and says so.

## 9. Responsive

Mobile is not a shrunk desktop. Breakpoints: **1180 · 960 · 860 · 720**.

- Navigation collapses to a single-row bar with a native `<details>` overflow — no JavaScript, no hydration cost.
- Finance tables become labelled cards: `.table-stackable` + `data-label` on each `td`.
- One primary action per screen, full width.
- Sticky in-page tab strips reposition under the shorter mobile top bar.
- Minimum touch target 40px (44px in link lists).

`td.num` reverts to start-aligned, wrapping text on phones — a right-aligned figure in a 40%-wide label/value grid is unreadable.

## 10. Accessibility

- `:focus-visible` ring everywhere, in a colour distinct from brand.
- Landmarks: `main#content`, skip link from `AppShell`, one `h1` per page (`Section` never renders `h1`).
- Tables get a `<caption>` (visually hidden) and `scope="col"` on headers.
- Forms: every field labelled, hints attached to the field, errors bound to the field and `role="alert"`.
- `prefers-reduced-motion`, `forced-colors: active`, and a print stylesheet that hides navigation and actions.
- RTL is **structural**, not a CSS mirror: logical properties only. `tests/design-system.test.ts` fails on any `margin-left`, `padding-right`, `border-inline-start` misuse, etc.

**RTL correctness note:** a back link points **right** in Arabic. The back arrows were `←`, which points *forward* in RTL reading; they are now `→`, and every back link uses one `.back-link` control. Flow separators inside a sentence (`مسودة ← تحقق ← اعتماد`) correctly keep `←` and were left alone.

Server-component-first, class-based, **zero new dependencies**.

## 13. What was deliberately not done

- No investor marketplace, discovery feed, funding flow, returns display, or ownership experience. Investor economics stay gated behind the open business decisions (BD-003/004/006/008) exactly as before.
- No invented financial metrics, returns, guarantees, urgency, scarcity, countdowns, social proof, or performance statistics.
- No new dependency. No mock data replacing real data.
- No business-rule, permission, route, or schema change.
