# خطة الإكمال السريع V2 — استخدام Odoo/ERPNext كخلفية محاسبية
**التاريخ:** 2 أغسطس 2026
**مُحدَّث بعد تعليق المستخدم على V1**

---

## 0. لماذا الخطة V1 لم تكن كافية (أنت محق)

الخطة السابقة اقترحت بناء دفتر الأستاذ والفواتير والبنوك يدوياً بأنفسنا (4 جداول + بضعة RPCs). هذا ممكن، لكن فيه مشكلتان قاتلتان لشخص واحد:
1. **بناء محاسبة صحيحة بلا أخطاء يتطلب 1000+ ساعة عمل واختبار سنتين على الأقل** — ERPNext بها ~1300 استعلام SQL في المحاسبة وحدها. Odoo أضخم.
2. **حتى لو بنيت دفتر أستاذ، ستبقى تفتقد:** فواتير مرقّمة تسلسلياً حسب القوانين، ضريبة قيمة مضافة متعددة، بنوك متعددة العملات، تسوية بنوك (مطابقة كشف حساب)، قيود يومية اعتيادية، عملاء وموردين بأرصدة افتتاحية، إهتلاك أصول ثابتة، أقفال سنة مالية، تقارير ضريبية... إلخ.

**الخلاصة:** لا يوجد مكوّن React منفصل يمكنك نسخه ويعطيك محاسبة صحيحة — المحاسبة منطق backend + قيود + سياسات محاسبية، وليست واجهة.

## 2. مقارنة Odoo vs ERPNext للخلفية المحاسبية

| | Odoo 18 Community | ERPNext v15 |
|---|---|---|
| الاستضافة Docker | أسهل، ملف docker-compose رسمي جاهز 2 خدم (odoo + postgres) | أصعب: يتطلب Frappe bench أو frappe_docker (4 خدمات: erpnext + mariadb + redis + nginx + socketio) |
| متطلبات RAM | 2GB كحد أدنى، 4GB مثالي | 4GB كحد أدنى، 8GB مثالي |
| الواجهة الأمامية | OWL framework | Vue.js |
| اللغة العربية | مدعومة رسمياً مع تقويم هجري وRTL | مدعومة |
| المحاسبة Community | ⚠️ فواتير + قيود + شجرة حسابات + COA + بنوك + عملات + أصول ثابتة | ✅ كاملة (أقوى من Odoo Community) |
| الـ API | XML-RPC/JSON-RPC ممتازة وسهلة | REST API عبر Frappe، أقل سلاسة |
| ZATCA/e-invoicing | modules مجانية في OCA (Odoo Community Association) | modules محلية |
| الزكاة/ضريبة | متوفرة في السوق السعودية | متوفرة لدول عربية |
| الـ Stack | Postgres (نفس قاعدة Terranex) | MariaDB (مختلف) |
| النضج | 18 سنة، 10 مليون مستخدم | 14 سنة، بضعة ملايين مستخدم |
| الرخصة | LGPL (تسمح بالاستخدام الداخلي بلا فتح الكود) | GPL-3 (استخدام داخلي مقبول) |

### توصيتي: **Odoo 18 Community**
الأسباب:
1. **Postgres نفسها** — أسرع تكاملاً ويمكنك نظرياً وضع Odoo و Terranex على نفس Postgres في المستقبل (لكن في البداية ضع قواعد منفصلة).
2. **Docker-compose بسيط جداً** (خدمتان فقط، يعمل على VPS بـ 4GB RAM بقيمة 6–12$ شهرياً، أو على جهازك محلياً).
3. **API أسهل** (JSON-RPC بسيط بـ fetch في TypeScript، بدون مكتبات خاصة).
4. **أخف على الجهاز** (2GB RAM تكفي لشركتك الصغيرة).
5. **نفس اللغة المحاسبية والقوائم المالية التي يعرفها أي محاسب عربي.**
6. **عندما تكبر لاحقاً يمكنك الترقية إلى Odoo Enterprise مقابل رسوم شهرية** (فيه ZATCA مدمج، OCR للفواتير، تصنيع، CRM).

**مهم:** لن تستخدم واجهة Odoo للمستخدم النهائي (لأنها غير مخصصة لنشاطك الاستثماري ولن تفهم توزيعات الأرباح والملكية المؤرخة). ستبقى واجهة Terranex العربية RTL هي الواجهة الوحيدة التي يستخدمها المستخدم، و Odoo يعمل خلف الكواليس.

## 3. خطة التنفيذ العملية (بالأيام)

### المرحلة صفر — تجهيز البنية التحتية (5 أيام)

#### 3.1 تثبيت Odoo 18 على نفس VPS (أو محلياً للتجربة) — يومان

أنشئ ملف `external/odoo/docker-compose.yml` في الريبو:

```yaml
# external/odoo/docker-compose.yml
version: '3.8'
services:
  web:
    image: odoo:18.0
    depends_on:
      - db
    ports:
      - "127.0.0.1:8069:8069"    # محلي فقط، لا تفتحه للإنترنت مباشرة
    volumes:
      - odoo-web-data:/var/lib/odoo
      - ./config:/etc/odoo
      - ./custom-addons:/mnt/extra-addons
    environment:
      - HOST=db
      - USER=odoo
      - PASSWORD=${ODOO_DB_PASSWORD}
    restart: unless-stopped
    deploy:
      resources:
        limits:
          memory: 3G

  db:
    image: postgres:16-alpine
    environment:
      - POSTGRES_DB=postgres
      - POSTGRES_PASSWORD=${ODOO_DB_PASSWORD}
      - POSTGRES_USER=odoo
      - PGDATA=/var/lib/postgresql/data/pgdata
    volumes:
      - odoo-db-data:/var/lib/postgresql/data/pgdata
    restart: unless-stopped
    deploy:
      resources:
        limits:
          memory: 1G

volumes:
  odoo-web-data:
  odoo-db-data:
```

**خطوات التثبيت (ستكون مكتوبة لك خطوة بخطوة وقت التنفيذ):**
1. استئجار VPS بسيط (Hetzner/DigitalOcean 2–4GB RAM بـ 6–12$/شهر) أو تشغيل Docker على جهازك.
2. نسخ ملف `.env.example` وإدخال كلمة مرور قوية.
3. `docker compose up -d`
4. الدخول على `http://localhost:8069` (أو VPS IP) وإنشاء قاعدة بيانات باسم شركتك مع اللغة العربية والدول (مصر/عُمان/السعودية) والعملة الأساس (OMR/EGP/SAR).
5. تثبيت الوحدات المطلوبة من Odoo Apps: **Accounting, Inventory, Contacts** فقط (الباقي لا نحتاجه).
6. Odoo سيُنشئ لك شجرة الحسابات تلقائياً باللغة العربية تبعاً للدولة التي اخترتها.

#### 3.2 إنشاء مستخدم API في Odoo — نصف يوم
أنشئ مستخدماً في Odoo بصلاحيات **Accounting Advisor** وأعطه API key. هذا هو المستخدم الذي سيستخدمه Terranex لإرسال القيود تلقائياً.

#### 3.3 مُهيّئ API في Terranex — يومان
أنشئ مجلد `src/core/odoo/` في Terranex:
- `client.ts` — عميل JSON-RPC بسيط يتعامل مع Odoo (authenticate + call_kw)
- `sync/` — مزامنات تلقائية (syncPartner، syncProjectAsCostCenter، postTransaction، postSettlement، postDistribution)
- `config.ts` — إعدادات الاتصال (URL، قاعدة البيانات، username، API key)

**حزمة npm التي ستساعدك:** ليست بحاجة لمكتبة — Odoo JSON-RPC يعمل بـ fetch مباشرة بسيط جداً (هذا جمال Odoo).

### المرحلة أ — ربط الكيانات الأساسية (5 أيام)

#### أ.1 مزامنة الشركاء (Partners) — يومان
**اتجاه المزامنة:** Terranex → Odoo (واحدية الاتجاه في البداية).
- عند إنشاء Partner في Terranex → نُنشئ مقابله contact في Odoo (عميل أو مورد أو شريك ملكية)
- نحفظ `odoo_id` في جدول partners بعمود جديد `odoo_res_id`
- لا مزامنة عكسية لتفادي الحلقات

#### أ.2 المشاريع كمراكز تكلفة (Cost Centers/Analytic Accounts) — يومان
Odoo لديه Analytic Accounting — كل Project في Terranex = حساب تحليلي في Odoo، يسمح لاحقاً بتقارير ربحية لكل مشروع من داخل Odoo أيضاً.

#### أ.3 المزامنات المالية — يوم
كل Transaction و Settlement و Distribution تُنشأ في Odoo كـ `account.move` (قيد يومية) آلياً عبر الـ API بعد حفظها في Terranex بنجاح — ضمن نفس العملية الذرية أو بواسطة queue لاحقة.

**مبدأ مهم:** **Terranex هو مصدر الحقيقة دائماً.** Odoo يستقبل ولا يُرسل (في المرحلة الأولى). أي خطأ في المزامنة يُسجل في جدول `sync_logs` ويعاد لاحقاً.

### المرحلة ب — استخدام Odoo لما يتفوق فيه (4 أسابيع)

**بمجرد تشغيل المزامنة، ستصبح كل هذه الميزات متاحة فوراً دون أي كود إضافي:**

| الميزة | طريقة الحصول عليها | جهد |
|---|---|---|
| شجرة الحسابات | جاهزة في Odoo باللغة العربية (اختر الدولة عند إنشاء القاعدة) | 0 |
| دفتر الأستاذ العام مزدوج القيد | جاهز في Odoo Accounting | 0 |
| ميزان المراجعة | تقرير جاهز | 0 |
| قائمة الدخل + الميزانية العمومية + التدفقات النقدية | تقارير جاهزة بـ AR/EN | 0 |
| فواتير مبيعات/مشتريات بأرقام تسلسلية قانونية | واجهة Odoo نفسها (للمحاسب) | 0 |
| ضريبة القيمة المضافة | جاهز مع التقارير الضريبية | 0 |
| حسابات بنكية متعددة العملات | جاهز مع التسوية اليدوية | 0 |
| تسوية بنكية باستيراد CSV/MT940 | وارد في Odoo | 0 |
| العملاء والموردين بأرصدة افتتاحية | جاهز (Contacts) | 0 |

| إقفال السنة المالية | جاهز في Odoo | 0 |
| الرقابة والصلاحيات | مجموعات صلاحيات جاهزة (محاسب، مدير، مستعرض) | 0 |

**هذا يعني أن كل الأشياء التي كنا سنبنيها في 3–4 أشهر تصبح متاحة فوراً — ونُركّز فقط على ربطها بـ Terranex.**

### المرحلة ج — إكمال النواقص في Terranex (4 أسابيع)

نكمل أجزاء Terranex الخاصة فقط (والتي لا توجد في Odoo):
1. ✅ شاشة "البنوك" في Terranex (تقرأ من Odoo وتعرض الأرصدة) — 3 أيام
2. ✅ شاشة فاتورة سريعة في Terranex (للمستخدم الذي لا يريد الدخول لـ Odoo) — خلف الكواليس تُرسل إلى Odoo وتُنشئ فاتورة حقيقية — أسبوع
3. ✅ Operational events — تحسينات وربط المخزون (عند `feed_consumption` في Terranex نُنشئ stock move في Odoo) — أسبوعان
4. ✅ بوابة الشركاء (investor portal) — ميزة التنافس الفريدة — 10 أيام
5. ✅ تقارير استثمارية خاصة (IRR، ربحية الموسم، تكلفة الرأس، إنتاجية الفدان) من Terranex (بيانات مالية من Odoo عبر API + بيانات تشغيلية من Terranex) — أسبوع
6. ✅ Mobile PWA للأحداث الميدانية — أسبوع

### المرحلة د — التميز والاعتماد (مستمر)
- ZATCA/ETA e-invoicing عبر وحدة OCA مجانية في Odoo (مثل `l10n_sa_zatca` السعودية أو `l10n_eg_eta` المصرية)
- البنوك: توجد وحدات استيراد كشف حساب لمعظم البنوك العربية في OCA
- CRM و HR يُضافان وقت الحاجة فقط (فعّل module من Odoo Apps)
- تكاملات أخرى دون أن تكتب كوداً (Odoo لديه 100 ألف تطبيق في متجره)

## 4. لماذا لن نستخدم واجهة Odoo للمستخدم النهائي؟

هذه النقطة مهمة جداً: Odoo واجهة عامة جداً لأي عمل، فيها 1000 قائمة وزر، ولن تفهم عملك الخاص:
- لا يوجد مفهوم "مشروع بشركاء متعددين بنسب ملكية تتغير بمرور الوقت"
- لا يوجد "تجميد لقطة ملكية عند التوزيع"
- لا يوجد "أحداث ولادة/نفوق/تحصين لقطيع" مع حساب الرصيد الحي
- لا يوجد "موسم زراعي" و"حصاد" وتكلفة الطن
- واجهته عامة جداً وصعبة لغير المُدرَّب عليها

**لذلك: واجهة Terranex هي البوابة الوحيدة التي سيفتحها المدير والشركاء والموظفون.** Odoo نافذة للمحاسب فقط لما يحتاج عمليات محاسبية متقدمة (تسوية بنك، إقفال سنة، تقارير رسمية للضرائب).

## 7. هل هناك مشاكل في هذا الأسلوب؟ صراحة

نعم، كن على علم بها:
1. **نقطتا فشل بدلاً من واحدة:** Odoo يحتاج أن يعمل أيضاً. لكن Docker + restart: always + نسخ احتياطية يومية يحلّان هذا.
2. **تعقيد الاستضافة الأولي:** ستحتاج تعلم أساسيات Docker و VPS — لكن هذا أسهل بكثير من كتابة محاسبة. سأكتب لك الأوامر جاهزة نسخ ولصق.
3. **تزامن أولي:** يجب نقل بيانات الأرصدة الافتتاحية إلى Odoo مرة واحدة بشكل دقيق — نكتب migration script لهذا.
4. **عند كسر المزامنة:** تحتاج آلية إعادة مزامنة (sync queue) سأبنيها لك.
5. **لا يمكنك استخدام Odoo Enterprise مجاناً** (لكن Community كاملة المحاسبة وفيها 90% مما تحتاج لسنوات).

**هذه العيوب كلها صغيرة مقارنة ببناء محاسبة كاملة وحدك.**

## 8. أين أصبحت نواة Terranex في هذا التصميم؟

**أكثر قيمة، لا أقل!**
السبب: عندما تزيل عبء كتابة المحاسبة عن كاهلك، يصبح تركيزك 100% على الأشياء التي تُميّزك فعلاً عن أي نظام عام:
1. ✅ **الشركاء والملكية المؤرخة** (Effective-Dated Ownership) — غير موجود في Odoo
2. ✅ **لقطات التوزيع المجمدة** (Immutable Distributions) — غير موجود في Odoo
3. ✅ **دفتر الشريك** (Partner Ledger) — Odoo لديه partner ledger بسيط وليس بعمق الخاص بك
4. ✅ **الأحداث التشغيلية** (ولادات، نفوق، تحصين، زراعة، حصاد) مع رصيد حي للماشية/المحاصيل — غير موجود في Odoo (Odoo livestock موجود كتطبيق ثالث وليس أصلياً)
5. ✅ **التقارير الاستثمارية الخاصة** (ربحية الموسم، أداء القطيع، مقارنة مواسم) — غير موجودة
6. ✅ **بوابة الشركاء** — غير موجودة في Odoo Community

هذه هي الميزات التي بعت عليها المشروع أصلاً — و Odoo سيتكفل بالبنية التحتية المملة التي لا تميّزك (ديون/دائنون، ضريبة، إهتلاك، تسوية بنك).

## 9. خطة بديلة لو رفضت فكرة Odoo

إذا قررت بعد ذلك أنك **لا تريد أي نظام منفصل** (لا Odoo ولا ERPNext)، هناك حل وسط جيد جداً:

**البديل: استخدم مكتبة محاسبة TypeScript/Postgres مفتوحة المصدر كأساس محاسبي، وليس ملفوفاً حول Odoo:**

المشروع الوحيد الذي وجدته مكتملاً للشركات الصغيرة: **HMB-research/open-accounting** (Go + SvelteKit + Postgres، MIT):
- Double-entry GL كامل
- فواتير، VAT، عملات متعددة
- حسابات بنك، تسوية بنك باستيراد CSV
- تقارير مالية كاملة (Balance Sheet، Income Statement، Trial Balance)
- Multi-company، multi-currency
- **المشكلة:** Frontend SvelteKit (ليس React)، Backend Go.

كيف نستخدمه؟ ننشره كخدمة منفصلة مثل Odoo ونتكامل معه عبر REST API. **ميزته على Odoo:** أخف بكثير (ذاكرة أقل)، أصغر حجماً، Postgres فقط، API REST عصري، ويمكن نظرياً **نسخ SQL schema والمنطق المحاسبي مباشرة** إلى Terranex (لأن كله Postgres فقط) دون خدمة منفصلة.

**لكن أوصي بـ Odoo لأنه:** ناضج جداً، مجتمع ضخم، عنده آلاف التطبيقات الجاهزة، كل محاسب عربي سيفهمه، والتدريب عليه متوفر مجانياً على يوتيوب.

- دقة محاسبية عالمية بدون أن نكتبها
